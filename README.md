# Backend-Development-Workspace
**Author:** Fiona Selders

## This respitory is my digitial notebook for the backend development course. I'll use it to track my projects, record what I learn, and keep useful reference materials.

## Overview

The workspace is organized so that everything for the course lives in one versioned place:

- **Unit folders** hold the work for each unit, each with its own README:
  - `unit-02-version-control/`
  - `unit-03-backend-scripting/`
  - `unit-04-advanced-scripting/`
  - `unit-05-restful-apis/`
- **`learning-log.md`** records my backend development goals and what I learn along the way.
- **`resources.md`** collects useful links for backend development, such as documentation and tutorials.
- **`git-reference.md`** is my personal Git command cheat sheet.

More unit folders will be added as the course continues. Each change is tracked with Git, so the commit history shows how the workspace grew.

## Learning Objectives

By the end of this course, I want to be able to:

1. Explain how backend systems work, including servers, requests, responses, and data flow.
2. Use Git and GitHub confidently, including committing, branching, and pushing changes.
3. Write backend scripts that automate tasks and work with data.
4. Build and use RESTful APIs with clear, well-designed endpoints.
5. Read documentation and debug errors on my own.
6. Keep a portfolio of projects that shows what I have learned.

## How I Plan to Use This Repository

- **Organize my work by unit.** Each project goes in its unit's folder, and each unit README describes what I built and how to run it.
- **Commit in small, meaningful steps.** Each commit does one thing and has a clear message, so the history tells the story of my progress.
- **Update the learning log regularly.** After each unit I will write down what I learned, what was hard, and what I want to improve.
- **Grow the resource list.** Whenever I find a helpful tutorial, doc, or tool, I will add it to `resources.md`.
- **Build my Git cheat sheet.** Whenever I learn a new Git command, I will add it to `git-reference.md` with a short explanation.
- **Review before finishing.** Near the end of the semester I will look back through the log and commit history to see how far I have come.
